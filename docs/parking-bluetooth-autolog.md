# 차량 블루투스 해제 시 주차 자동 기록이 안 된 원인과 재설계

> 작성: 2026-10-10 (KST) · 대상: 주차 기록 아티팩트("어디 세웠지") + MacroDroid
> 공개 저장소이므로 아티팩트 링크·좌표·장소명·알림 토픽은 적지 않는다.

## 1. 결론

자동 기록은 **한 번도 동작한 적이 없다.** 이번 한 번만 실패한 것이 아니다.

- 주차 DB에 있는 기록 5건이 **모두 `source: manual`** 이다. MacroDroid 경로로 들어온 기록(`macrodroid`·`recovered`)은 0건이다.
- 10-10 기록은 10:15 시작인데 생성 시각이 11:11이다. 56분 뒤에 손으로 소급 입력한 것이고, 출차 시각 12:24도 16:48에 손으로 넣었다.

현재 구조는 처음부터 "자동"이 아니었다. 기록이 생기려면 사람이 MacroDroid 알림을 **눌러서** 페이지를 열어야 하고, 그 페이지가 URL 해시(`#t…`)를 받아야 한다. 이 경로에서 실제로 검증된 단계는 마지막 하나뿐이다.

## 2. 고장 사슬

| # | 단계 | 검증 여부 | 근거 |
|---|---|---|---|
| 1 | 차량 블루투스 끊김 → MacroDroid 트리거 | ✗ 미검증 | 매크로 설계(트리거·액션·기기명)가 어느 세션에도 없다 |
| 2 | 위치 측정 → URL 조립 `#t<ms>_<lat>_<lng>_e<ms>_s<ms>` | ✗ 미검증 | 형식은 페이지 코드 주석에만 있다 |
| 3 | 알림 표시 | ✗ 미검증 | |
| 4 | **사람이 알림을 탭** | 설계상 필수 | 페이지 문구: "MacroDroid 알림을 눌러 열어 주세요" |
| 5 | 브라우저 또는 Claude 앱이 claude.ai 링크를 연다 | ✗ 미검증 | 앱 링크 가로채기·로그인 리다이렉트 중에 해시가 살아남는지 모른다 |
| 6 | 바깥 페이지가 해시를 샌드박스 iframe에 넘긴다 | ✗ 미검증 | 런타임 문서에 해시 전달 보장이 없다 |
| 7 | 페이지가 `parseHash` 후 `createParking(..., 'macrodroid')` | ✓ 로컬 Playwright만 | 실제 claude.ai URL로는 시험한 적 없다 |

기록이 0건이므로 1~6 중 적어도 한 곳이 매번 끊겼다. 어디서 끊겼는지는 폰 로그 없이 판별할 수 없다. 다만 어디서 끊겼든 결론은 같다. **4는 사람 의존이고, 5·6은 플랫폼 동작이라 우리가 통제할 수 없다.** 이 경로를 고쳐 써서는 "자동"이 될 수 없다.

### 고장이 사흘간 드러나지 않은 이유

미출차 루틴은 "24시간 넘게 열려 있는 기록"만 본다. **기록이 아예 안 생긴 경우는 보지 못한다.** 실패가 조용했다.

## 3. 재설계 원칙

**캡처와 기록을 분리한다.**

- 폰은 이벤트를 파일에 **덧붙이기만** 한다. 네트워크·탭·브라우저와 무관하다.
- 기록은 서버 쪽에서 만든다(루틴 + 페이지).
- 사용자 기존 자산을 그대로 쓴다. 같은 패턴이 이미 돌고 있다(카드 실적 `card-log.txt`, 수면 `sleep_log.csv`).
  - 폰: MacroDroid 파일 쓰기 → Autosync → Drive
  - 서버: 루틴이 Drive 파일을 읽는다

```
[BT 끊김/연결] → MacroDroid "파일에 쓰기(추가)" → parking_log.csv (Autosync 폴더)
                                                   │ Autosync
                                                   ▼
                                              Google Drive
                                       ┌──────────┴───────────┐
                         루틴(하루 4회, Drive 커넥터)    페이지 열 때(mcp 기능, Drive)
                                       └──────────┬───────────┘
                                                   ▼
                                    주차 DB parkings (id = p<끊김 ms>, 멱등)
```

## 4. 실행 계획

### 0단계 — 오늘 실패 지점 확정 (판별용)

MacroDroid **시스템 로그**에서 10-10 10:10~10:20에 매크로가 실행됐는지 본다.

| 로그 상태 | 끊긴 곳 |
|---|---|
| 실행 기록 없음 | 1 (트리거·기기명·배터리 최적화) |
| 실행 기록 있음 | 3~6 |

어느 쪽이든 아래 재설계로 간다. 이 단계는 원인 기록용이다.

### 1단계 — 캡처 (폰)

**매크로 A「주차-끊김」**

- 트리거: 블루투스 이벤트 → **차량 기기 이름 지정** → 연결 끊김
- 액션 ①: 위치 강제 갱신 — 타임아웃 30초, 네트워크 위치 허용
- 액션 ②: 파일에 쓰기, **추가 모드**. 파일은 Autosync 동기화 폴더의 `parking_log.csv`
  - 한 줄: `<시스템시각 ms>,OFF,<위도>,<경도>,<정확도m>`
  - 위치를 못 받으면 좌표 칸을 비운다. 그래도 **줄은 반드시 쓴다.** 위치는 부가 정보다.
- 액션 ③(선택): 알림 "주차 기록됨 · 층 입력". 탭하면 **해시 없는** 페이지 링크가 열린다. 눌러도 되고 안 눌러도 기록은 생긴다.

**매크로 B「주차-연결」**

- 같은 기기의 블루투스 연결 → `<ms>,ON,,,`

**폰 설정**

- MacroDroid·Autosync **배터리 최적화 제외**
- MacroDroid 위치 권한 "항상 허용"

### 2단계 — 반영 (서버)

**(a) 루틴「주차 BT 로그 반영 + 미출차」**

- 기존 미출차 루틴을 대체한다.
- Drive 커넥터가 필요하다. 세션 안에서 만든 루틴에는 커넥터가 붙지 않으므로 **claude.ai 루틴 화면에서 만든다.**
- 실행: 하루 4회 (05:57 · 11:57 · 17:57 · 22:57 KST)
- 처리 규칙:
  1. `parking_log.csv`를 읽는다. 충돌 사본이 있으면 합친 뒤 중복을 제거한다.
  2. OFF→다음 ON을 짝지어 기록 하나로 만든다. id는 `p<OFF ms>`이며, 페이지와 같은 규칙이라 멱등이다.
  3. **디바운스**: OFF→ON 간격이 3분 미만이면 무시한다(신호 끊김·재시동).
  4. 수동 기록과 시작 시각이 ±20분 안이면 새로 만들지 않는다. 그 수동 기록에 좌표·종료 시각만 채운다. 층·메모는 보존한다.
  5. `source: 'bt-log'`, 장소 반경 매칭은 페이지의 `matchPlace`와 같은 규칙.
  6. ArtifactData batch로 쓴다(`if_version`).
- 이어서 기존 미출차 판정과 알림을 그대로 한다.

**(b) 페이지 즉시 반영**

- 페이지에 `mcp` 기능을 선언한다. Google Drive의 `search_files`·`download_file_content` 두 도구만 쓴다.
- 열릴 때 같은 로그를 읽어 같은 규칙으로 반영한다. 루틴이 돌기 전이라도 페이지를 열면 바로 보인다.
- 처음 한 번 연결 동의가 필요하다.
- 해시 경로(`parseHash`)는 하위 호환으로만 남기고 안내 문구에서 뺀다.

### 3단계 — 조용한 실패 감시

루틴이 매 회차 다음을 판정한다.

- **로그 끊김**: 마지막 BT 이벤트가 72시간 넘게 없으면 → "주차 BT 로그 끊김 — MacroDroid·Autosync 확인" 알림
- **짝 불일치**: OFF만 연속 2개 이상(ON 누락)이면 보고에 적는다
- 기존 「루틴 감시」가 이 루틴의 미실행·실패를 함께 잡는다

### 4단계 — 검증 게이트 (순서대로, 통과해야 다음)

| 게이트 | 방법 | 통과 기준 |
|---|---|---|
| G1 | MacroDroid에서 매크로 A·B 테스트 실행 | Drive의 `parking_log.csv`에 2줄. Autosync 지연을 측정해 기록 |
| G2 | 실제 시동 끄기 → 켜기 1회 | 실제 이벤트 2줄, OFF 줄에 좌표 유무 확인 |
| G3 | 루틴 시험 실행 | DB에 `bt-log` 1건, 재실행해도 중복 0 |
| G4 | 페이지 열기 | 루틴 전에도 해당 주차가 보임 |
| G5 | 7일 운영 | BT OFF 이벤트 수(디바운스 후) = DB 기록 수 |

## 5. 남는 위험

| 위험 | 영향 | 대응 |
|---|---|---|
| 지하 주차장 위치 부정확·실패 | 장소 자동 인식만 실패. 기록은 생김 | 반경 200m 유지, 좌표 없으면 장소 칩으로 지정 |
| Autosync 지연·중단 | 반영이 늦어짐 | 3단계 로그 끊김 감시 |
| 배터리 최적화로 매크로 미실행 | 이벤트 누락 | 1단계 제외 설정, G5로 계수 검증 |
| 다른 사람이 운전(폰 블루투스 미연결) | 기록 없음 | 구조적 한계. 수동 시작 버튼 유지 |
| 로그 파일에 집 좌표가 쌓임 | 개인정보 | 비공개 Drive 폴더에만 둔다. 공개 저장소·공개 토픽 금지 |
