# KST 날짜 혼동 문제와 해결

> 작성: 2026-10-05 (KST) · 대상: Claude Code 클라우드 세션 (claude.ai/code)

## 1. 증상

"오늘 오후 2시"로 일정을 잡으라고 하면, Claude가 날짜를 하루 앞으로 잡았다가 나중에 KST 기준으로 다시 고친다. 이 일이 반복된다.

### 실제 사례 (2026-10-05 세션)

| 시각 (KST) | 일어난 일 |
|---|---|
| 10-05 07:02 | 요청: "선아 뱅크샐러드 내용 CSV로 받기, 오늘 오후 2시" |
| 10-05 07:02 | 일정을 **10-04** 14:00 (+09:00)로 생성 → 이미 지난 시각 |
| 10-05 07:02 | 캘린더 응답의 `created: 2026-10-04T22:02:27Z`를 보고 날짜가 틀린 것을 발견 |
| 10-05 07:02 | 일정을 **10-05** 14:00 (+09:00)로 수정 |

## 2. 원인

틀린 것은 **시간대(오프셋)가 아니라 날짜**다. 처음 생성할 때부터 `+09:00`과 `Asia/Seoul`은 들어가 있었다.

원인은 세 가지가 겹친 것이다.

1. **컨테이너 시계가 UTC다.** 클라우드 컨테이너는 `TZ`가 설정되어 있지 않다. 그래서 `date`가 `Sun Oct 4 22:06:28 UTC 2026`을 출력한다.
2. **Claude가 받는 "오늘 날짜"도 UTC 기준이다.** 세션 컨텍스트에 `Today's date is 2026-10-04`가 들어왔다. 같은 시각 한국은 이미 10-05였다.
3. **이를 바로잡는 지침이 없었다.** 저장소에도 `~/.claude/`에도 CLAUDE.md가 없었다. 그래서 Claude는 UTC 날짜를 그대로 "오늘"로 썼다.

### 언제 터지는가

UTC와 KST의 날짜는 **KST 00:00–08:59** 사이에 어긋난다(UTC 15:00–23:59, 하루 9시간).
이 시간대에 "오늘/내일/모레"를 말하면 날짜가 하루씩 밀린다. 아침에 일정을 잡을 때 매번 틀린 이유가 이것이다.

## 3. "CLAUDE.md에 KST 기준을 넣었어야 했다" — 맞는가

**부분적으로만 맞다.** CLAUDE.md는 필요하지만 그것만으로는 충분하지 않다.

| 한계 | 설명 |
|---|---|
| 기본 브랜치 병합 필요 | 새 세션은 기본 브랜치(`main`)를 새로 받아 시작한다. 작업 브랜치에만 있는 CLAUDE.md는 다음 세션에서 읽히지 않는다. |
| 저장소 단위 | `upbit` 저장소 세션에만 적용된다. 다른 저장소 세션이나 claude.ai 일반 채팅에는 적용되지 않는다. |
| 지시일 뿐, 시계를 바꾸지 않음 | 컨텍스트의 "Today's date"와 `date` 출력은 여전히 UTC다. Claude가 규칙을 따라야만 맞게 나오므로, 빠뜨릴 여지가 남는다. |

**근본 해결은 시계 자체를 KST로 바꾸는 것(환경 변수)이다.** CLAUDE.md와 개인 설정은 그 위에 얹는 보조 장치다.

## 4. 해결 방법 (3단계)

| 단계 | 방법 | 적용 범위 | 강제력 |
|---|---|---|---|
| ① 환경 변수 | 클라우드 환경에 `TZ=Asia/Seoul` | 이 환경을 쓰는 모든 세션 | 높음: 시계 자체가 KST |
| ② CLAUDE.md | 저장소 맨 위 `CLAUDE.md`의 시간대 규칙을 `main`에 병합 | `upbit` 저장소 세션 | 중간: Claude가 따르는 규칙 |
| ③ 개인 설정 | claude.ai 개인 설정(사용자 선호)에 KST 규칙 한 줄 | claude.ai 채팅 + 모든 Claude Code 세션 | 중간: Claude가 따르는 규칙 |

### ① 환경 변수 `TZ=Asia/Seoul`

- 위치: 세션 제목 표시줄의 클라우드 환경 메뉴 → **Edit** → 환경 변수
- 입력값:
  ```
  TZ=Asia/Seoul
  ```
- 적용 시점: **새 세션부터** (현재 세션에는 적용되지 않음)
- 효과: `date`, Python `datetime.now()` 등 컨테이너 안의 모든 시각이 KST로 나온다.
- 확인 필요: 세션 컨텍스트의 "Today's date"도 KST로 바뀌는지는 검증하지 않았다. §5의 2번 항목으로 확인한다.

### ② CLAUDE.md (`main` 병합)

`CLAUDE.md`에 들어간 규칙:

```markdown
## 시간대 규칙 (필수)

- 사용자는 대한민국에 있다. 모든 날짜·시간의 기준은 KST (Asia/Seoul, UTC+09:00) 이다.
- 이 실행 환경(클라우드 컨테이너)의 시계는 UTC다. 시스템이 알려주는 "Today's date"와
  `date` 출력은 UTC 기준이므로 그대로 "오늘"로 쓰지 않는다.
- "오늘", "내일", "오후 2시" 같은 상대적 표현은 반드시 먼저 KST 현재 시각을 확인한 뒤 해석한다:
  `TZ=Asia/Seoul date '+%Y-%m-%d %H:%M %Z'`
  (UTC 15:00 이후는 KST로 이미 다음 날이다.)
- Google 캘린더 일정 생성·수정 시:
  - startTime/endTime은 +09:00 오프셋으로, timeZone은 Asia/Seoul로 지정한다.
  - 기본 캘린더는 wsc627@gmail.com (Asia/Seoul).
  - 종료 시간이 지정되지 않으면 30분으로 잡는다.
- 사용자에게 시간을 보여줄 때는 KST로 표기한다. UTC는 필요할 때만 괄호로 덧붙인다.
```

- 현재 상태: 브랜치 `ccr-36c1176a-9irb9l`에 커밋되어 있음 (`e9742a8`). `main`에는 아직 병합되지 않음.

### ③ claude.ai 개인 설정

- 위치: claude.ai → Settings → Profile → 개인 설정(사용자 선호)
- 추가할 문장:
  ```
  • 나는 대한민국에 있다. "오늘/내일/몇 시"는 항상 KST(Asia/Seoul) 기준으로 해석하고, 시스템 날짜가 UTC일 수 있으니 KST로 환산해 확인하라.
  ```
- 근거: 현재 개인 설정이 이 Claude Code 세션의 시스템 프롬프트에도 들어와 있다. 그러므로 저장소와 관계없이 모든 세션에 적용된다.

## 5. 적용 상태와 검증

| 항목 | 상태 |
|---|---|
| CLAUDE.md 작성 | 완료 (브랜치 `ccr-36c1176a-9irb9l`, 커밋 `e9742a8`) |
| CLAUDE.md `main` 병합 | 미완료 |
| 환경 변수 `TZ=Asia/Seoul` | 미완료 |
| 개인 설정 문장 추가 | 미완료 |

새 세션에서 KST 00:00–08:59 사이에 아래를 확인한다.

1. `date` 실행 → `KST`가 나오면 ①이 적용된 것
2. "오늘 며칠이야?" 질문 → KST 날짜로 답하면 정상
3. "오늘 오후 2시 일정 잡아" 요청 → 처음부터 KST 날짜, `+09:00`으로 생성되고 수정 없이 끝나면 해결

## 레퍼런스

- 컨테이너 확인 결과 (2026-10-05 세션): `TZ=`(비어 있음), `date` → `Sun Oct 4 22:06:28 UTC 2026`, `TZ=Asia/Seoul date` → `2026-10-05 07:06 KST`
- Google Calendar API 응답: `"created":"2026-10-04T22:02:27Z"`, 수정 후 `"start":{"dateTime":"2026-10-05T14:00:00+09:00","timeZone":"Asia/Seoul"}`
- CLAUDE.md 로딩 방식: https://code.claude.com/docs/en/memory
- 클라우드 세션 환경(환경 변수, 브랜치 클론): https://code.claude.com/docs/en/claude-code-on-the-web
- `TZ` 환경 변수 규격: https://www.gnu.org/software/libc/manual/html_node/TZ-Variable.html
